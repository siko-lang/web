Effect Handlers in Depth

Effect handlers are the mechanism by which abstract effect operations are given concrete implementations. This page covers the advanced mechanics.

Handler Signatures

A handler for an effect method must match the method's signature exactly. The handler itself can be generic as long as the type variables can be inferred from the call site:

effect Printer {
    fn print_value(s: String)
}

fn generic_handler[T: ToString[T]](value: T) {
    println(value.to_string())
}

fn main() {
    with print_value = generic_handler {
        Printer.print_value("hello")
    }
}

Nested Handlers

Handlers can be nested. The innermost with block wins for any given effect method:

with log = file_log {
    Logger.log("goes to file");
    with log = console_log {
        Logger.log("goes to console");
    }
    Logger.log("goes to file again");
}

Handlers Calling Effects

A handler can itself call other effect methods. The handler runs in the same effect context as the call site, so it inherits all active handlers:

fn logging_handler(msg: String) {
    Metrics.increment("log_count");
    println(msg);
}

Here Metrics.increment must also have a handler in scope at the with site.
