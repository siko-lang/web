Effects & Implicits: Two Years In

When we started Siko, effect systems were a research curiosity. Most production languages either ignored them entirely or bolted them on as syntactic sugar over monads. We wanted something that felt native — where swapping a handler was as natural as passing an argument.

The core insight is that effects and implicits solve different problems. An effect is about behaviour: what happens when you call read_line() depends entirely on which handler is in scope. An implicit is about context: a piece of data that threads through call chains without appearing in every signature.

effect TeleType {
    fn read_line() -> String
    fn println(input: String)
}

fn run() {
    while True {
        let input = read_line();
        if input == "exit" { break; }
        println("You said: ${input}");
    }
}

The with block wires handlers at the call site. In tests you pass mocks; in production you pass the real I/O functions. The compiler enforces that every effect method has a handler in scope — no runtime surprises.

Two years in, the model has held up. The biggest surprise was how cleanly effects compose with the trait system: a generic handler like fn log[T: ToString[T]](value: T) can be wired to a non-generic effect method, and the monomorphizer figures out the type args from the call site.
